# Requerimientos funcionales

Los requerimientos funcionales de CloudOps Client Hub se identifican como RF-nn y se priorizan con el método MoSCoW (M = debe, S = debería, C = podría, W = no esta vez). Se conservan los 25 identificadores definidos al inicio del proyecto y se añaden cuatro (RF-26 a RF-29) para funciones que se construyeron después de la primera versión del plan: el alta de un sitio por GitOps, la voz del asistente, el RAG y el registro de modelos. La Tabla {T:rf} resume cada requerimiento con su criterio de aceptación y su estado real.

El estado se determinó leyendo el código, no la documentación: **Hecho** indica que la función existe, está cubierta por pruebas automatizadas y se ejecutó al menos una vez de punta a punta; **Parcial** indica que existe, pero no cubre todo lo que el requerimiento enuncia (la salvedad se explica en la tabla); **Diferido** indica que no se construyó y queda como mejora; **Fuera de alcance** indica una decisión explícita de no construirlo. En la fecha de revisión (16 de noviembre de 2026) la suite del backend recoge 1.134 pruebas (`docker compose exec api pytest --collect-only`).
